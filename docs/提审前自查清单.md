## 3. 隐私与安全

- ✅ 客户端代码里搜不到 API Key（`sk-`、`Authorization`、`deepseek.com` 均无宿主域名直连）
- ✅ 小票图片走云存储中转，识图后立即删除（不落库）
- ✅ 权限在**云端强制**：非成员无法跨房间读写；撤销/编辑有角色校验
- ✅ 账目软删除（`revoked`），结清留流水，可追溯
- ☐ 隐私指引里写明"小票图片会发送给第三方 AI 服务用于识别，识别后即删除"
- ☐ 确认没有任何"诱导分享/诱导关注"文案（分享是纯工具入口）

## 4. 审核常见驳回点与应对

| 驳回理由 | 我们的情况 | 应对 |
|---|---|---|
| 类目与功能不符 | 记账工具选"工具>效率" | 若被驳，改投生活服务类目，不改形态 |
| 涉及金融/支付 | 不做支付、不放贷、不托管资金 | 简介与协议里已明示；被问就强调"只记录不支付" |
| 功能不完整/无法使用 | 演示数据、清空、导入 JSON 已对正式版隐藏 | 提供测试说明：任意微信号可自建房间 |
| 缺少隐私授权 | 已提交隐私指引；相册/剪贴板为系统授权 | 若被驳，补 `onNeedPrivacyAuthorization` 自定义弹窗 |
| 图片识别无审核 | 图片仅用户本人可见、不公开传播 | 说明"非 UGC 公开展示场景" |

## 5. 提交步骤

1. 开发者工具 **编译**（确认无红字）→ **上传**（版本号 `1.0.0`，备注写本次内容）
2. 公众平台 → 版本管理 → 开发版本 → **提交审核**
3. 审核信息里填：功能页面说明 + 测试路径（"微信登录即可自建房间，无需账号"）
4. 通过后 → **发布**（备案未通过时发布按钮会置灰）

## 6. 上线后回滚预案

| 情况 | 处理 |
|---|---|
| 云端出现写入异常 | `config/env.js` 的 `cloudLedger` 改 `false` 发版，回到本机模式（数据不丢） |
| 云函数报错 | 云开发控制台看日志；用 CLI 回滚部署（`cli cloud functions deploy --names <fn>`） |

## 7. 驳回记录与应对（2026-11-01）

**驳回理由（原文）**

> 小程序服务内容涉及深度合成技术（如 AI 问答、AI 换脸视频、AI 绘画等），属个人主体尚未开放服务类目，建议申请企业主体类型小程序。

**原因判断**：不是功能本身，而是**界面文案**——审核截图里出现了「AI 识图」「AI 读图中…」「让 AI 帮你说这句话」，被归类为深度合成内容。

**已做的处理**

| # | 改动 | 位置 |
|---|---|---|
| 1 | 界面文案去掉「AI」：自动识别 / 识别中… / 识别这张小票 | 小票页 |
| 2 | 报错文案去掉「AI」：识别失败、识别服务未配置、识别服务太忙… | 小票页 + 云函数 ai |
| 3 | 隐私政策改为「第三方云端识别服务」；用户协议改为「小票识别属于辅助功能」 | 关于页 |
| 4 | 首页提醒话术改为「让系统帮你把这句话说好」 | 首页 |
| 5 | 云端返回的 provider 从「AI 识图 · 模型名」改为「小票识别」 | 云函数 ai |
| 6 | 新增开关 receiptOcr：false 时隐藏拍照入口，只留粘贴文字 | config/env.js |

**再次提审时，审核说明建议直接粘贴：**

```
本小程序是寝室公共开支记账工具，不提供任何内容生成服务。
「小票识别」仅用于识别用户自己拍摄的购物小票上的金额与品名，
识别结果只回填到用户自己的账本，不生成图片/视频，不涉及人脸、
换脸、绘画、对话等深度合成功能。
若对拍照入口仍有疑虑，可关闭拍照功能（仅保留粘贴文字），
记账与分摊功能完全不受影响。
```

**兜底方案**：若仍被拒，把 `miniprogram/config/env.js` 的 `receiptOcr` 改成 `false` → 重新编译上传 → 小票页只剩「粘贴票面文字」，功能依然完整。

**提交前自查**：`node tools\check-release-text.js`，确认界面字符串里没有 AI 字样。
